# 文献库构建流水线

## 唯一的判据：页码主线

这套流水线只守两条线，其余都是实现细节：

- **页码主线**——页码从扫描页一路贯通到库内字段、再到论文标注。这条线一断，检索得到的文本就无法回答"这句话在原书第几页"。所以页码在**文本化阶段**就要落进文本标记，不留到入库后补。
- **留空胜过猜测**——最危险的不是"读不出来"，而是"**读错但看起来对**"。读不出来就记 `status`，推不出页码就留 `NULL`，没核实就标"待回查纸本"。

## 访谈材料是**另一个分支**（不是本流水线的一步）

访谈材料（音频 → 转写稿）没有印刷页码，锚点只能是**时间码**；照搬本流水线的阶段 2–5 没有对象。它有自己的判据、七步流程与四个专用工具，**动手前读**：`<DSH_WORKSPACE>\文档\规范\访谈材料数据库工作方法.md`

五个必须知道的差异（详见该文档 §1、§4）：

- 锚点：`page_start/page_end` 对 txt/md **恒为 NULL**（引擎 docstring 明说）→ 时间码写进小节标题，让 `section` 带时点。
- 元数据：只能靠**文件名** `受访者代号 - 年份 - 会话名`（只用年份；带完整日期会被解析成 `year=2024, title=03-11 - …`）。
- 查询语言：中文访谈库**直接用中文问**（实测 Top-1 6/6，英文只有 3/6）——BM25 只对 CJK 二元组建索引。
- 五类**静默失败**：附录/致谢标题整节丢弃、正文 <40 字符整节丢弃、中文无切点造成巨型分块、非 UTF-8 静默乱码、正文段落被当标题（首词被吃掉）。入库前必须用 `_interview_check.py` 干跑一遍。
- 治理：**脱敏必须在入库之前**——检索片段会进云端模型 prompt，用了这套工具就不是本地封闭处理。

## 步骤与验收门

每一步都以**验收门通过**为完成标准；门不过就停在那里解决，不进入下一步。

1. **素材体检** → 每件页数已知；无文字层的单独列出。
2. **版式预检** → 栏数判定有依据；低置信页列入清单。
3. **文本化**（三条路线择一：版式感知 OCR / docx 页眉法 / OCR 转印刷页码） → 页标记连续且等于源文件页数；页眉与页下注已分离。
4. **页码标定** → 偏移量**自证**：命中页文本里真的印着推算出的页码，且差值**成片**而非散点。
5. **口径统一** → 全库页标记＝**印刷页码**；换算前后引文页码逐条一致。
6. **入库**（`kb_ingest`） → 条数明确；块数＝向量数。
7. **结构核查** → 悬空 0；`chunk_count` 零不一致；无同 sha256 重复；页码覆盖率与元数据缺失面已量化。
8. **检索验证** → 逐字引文用 `mode=keyword` 能 Top-1 命中；`filters.section` 能定位到指定页。
9. **引文定位** → 每条候选都有页内原文印证。
10. **交叉验证** → **两条独立路径**算出的页码一致才允许写入论文。
11. **校勘与回填** → 引文与命中页原文逐字对比，差异逐条列出；未核实的标"待回查纸本"。
12. **治理** → 写库前有备份、写后计数不增反减即报警。

## 三个必知的坑（环境不承认、`--help` 也查不到）

- **`kb_root` 默认指向当前会话工作区的 `.kb`**，而项目库常在别处。跨项目查库必须传绝对路径，否则会返回"知识库为空"，看起来像数据丢了。
- **`kb_root` 必须是「直接包含 `kb.sqlite` 的目录」**（通常是 `<项目>/.kb`）。写错路径时 `kb_engine.connect()` 会 `mkdir` + 建一个**空壳库**，"看起来像库是空的"——本项目已踩过两次（曾出现一个 32 KB 的空 `kb.sqlite`）。**只读体检工具一律用 `file:...?mode=ro` 打开，路径错就报错、绝不创建**（`_interview_verify.py` 就是这么做的，自测里有一项专门验证）。
- **`toolkit_*` 这组 DSH 工具**曾全部报 `output.render failed: userRender is not a function`（插件缺 `output.render`），现已修复：本次会话实测 `toolkit_search` 正常返回。若再遇到该报错，改用命令行：`python <REPO>/tools\toolkit.py <命令>`，或各工作区的 `.tools\run.py`。

## 写操作前的固定动作

改库之前先备份、先试运行、写完立刻核对关键计数。`_kb_guard.py` 就是这道闸：先 `--selftest` 自测，再 `KbGuard(DB, reason="…")` 进出。
