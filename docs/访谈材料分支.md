# 访谈材料数据库工作方法（文献库流水线的**访谈分支**）

> **这份文档是什么**：把「访谈录音 → 转写稿 → 可检索、可按时点引用的访谈库」的全过程，统一成一套流程、验收门、工具与失败模式。
> **这份文档不是什么**：不是文献库 SOP 的补充说明。访谈材料在**五个维度**上与文献根本不同（见 §1），照搬文献库流程会踩到五类**静默失败**——不报错、也没有告警，但材料不见了或无法引用。§4 逐条给出源码位置与复现证据。
> **依据**：`kb_engine.py` **3.2.0/rev5** 源码逐段核对（不是推测）＋ 4 个新工具的 **71 项自测**＋ 一次实跑实验（2026-09-16）。
> **与文献库共用的部分**：同一个引擎、同一套治理层（备份/守卫/验收思路）、同一个 `kb_root` 陷阱。
> **文献库流程**：见 `文献库构建SOP.md`（十二步、页码主线）。两者是**并列的两个方法**，不是一个方法的两个阶段。

---

## 0. 三条判据

**判据 1：锚点是时间码，不是页码。**
引擎源码明说页码是 PDF 物理页，"**txt/md/docx 无页（None）**"。访谈转写稿是 txt/md，所以 `page_start/page_end` **恒为 NULL**——文献库那条"引文能落回印刷页码"的主线在这里**没有对应物**。访谈库的可引用性只能建立在**时间码 + 说话人**上。引用格式：`[A03 2024-03-11, 00:12:35]`。

**判据 2：留空胜过猜测（沿用文献库），并追加"证据必须能归属到人"。**
读不出来就留空；推不出时点就不写。此外：访谈研究里"谁说的"是证据的一部分，因此**每轮都要有说话人标签**——没有标签的命中结果无法支撑论证。

**判据 3：脱敏必须在入库之前。**
检索出的片段会进入云端大模型的 prompt（`kb_search`/`kb_rag` 的 evidence 就是这么用的）。也就是说，用了这套工具就**不是本地封闭处理**。脱敏只能前置，不能"入库后再清理"。

> 判据 3 是三条里最容易被技术与流程挤掉的，而它的后果不可逆（信息一旦进入云端请求就无法收回）。

## 1. 与文献库的差异（一张表定分工）

| 维度 | 文献库 | 访谈库 |
| --- | --- | --- |
| 唯一判据 | 页码主线 | **时间码主线 + 说话人归属** |
| 素材起点 | PDF / 扫描件 / docx | **音频 → 转写稿**（音频层**不在**本工具链内，见 §2 步骤 1） |
| 章节来源 | 书刊章节、页标记 | `#`/`##` 标题（把时间码写进标题即可进 `section`） |
| 切分陷阱 | 双栏、页眉页脚 | **中文句末标点后无空白 → 巨型分块** |
| 元数据 | 标题/作者/年份/期刊/**DOI** | 受访者代号/年份/会话名（**文件名驱动**）；无 DOI（NULL 是正确结果） |
| `journal` 字段 | 可由 Zotero 填 | 无意义（`extract_meta` 里该字段恒为 None，只有 Zotero 迁移能填） |
| 查询语言 | 中文库用中文；英文库转英文术语 | **中文直接问**（实测 6/6 vs 英文 3/6，见 §7） |
| 引用格式 | 第 N 页 | `[受访者代号 日期, 时间码]` |
| 核心风险 | 页码错但看起来对 | **材料静默消失** + **伦理合规** |
| 体量 | 十万块级需考虑索引化 | 通常几千块，**不是瓶颈**（§7） |

**结论**：文献库 SOP 的阶段 2（版式预检）、3（文本化三条路线）、4（页码标定）、5（口径统一）在访谈材料上**没有对象**；访谈库需要的是"转写格式治理 + 静默失败体检"这一段。

## 2. 七步流程

每步给：**做法 → 工具 → 验收门（DoD）→ 不达标处置**。门不过就停在那里。

### 步骤 1　转写与素材准备

| 项 | 内容 |
| --- | --- |
| 做法 | 音频转文字。**必须保留时间码与说话人**；转写规范见 §5 |
| 工具 | **无**。工具库 133 条里没有任何转写工具（`toolkit_search` 查"转录/音频/whisper" **0 命中**，同法查 "ocr" 有 10 命中，可对照） |
| 产物 | 每场访谈一份 `.md`/`.txt`（UTF-8） |
| **验收门** | 每场有时码、有说话人标签；编码为 UTF-8（或已知的 GB18030） |
| 不达标 | 转写质量是整条链的上限，**这一步糊弄，后面全部无效**。技术路线（本地模型/云服务/人工）需自行决定，本方法不涉及 |

> ⚠️ 方言、口语、填充词上的转写与检索质量**我没有实测数据**，不构成建议。

### 步骤 2　脱敏（**必须在入库前**）

| 项 | 内容 |
| --- | --- |
| 做法 | 人名/地名/单位/联系方式/可识别细节 → 化名。**化名映射表单独保管**（它是唯一能把化名还原到真人的东西，属最高敏感资产） |
| 工具 | `_interview_check.py` 的 PII 扫描（手机号/固话/身份证/邮箱/长数字串/地址触发词，**只报类型+行号+掩码，不落原文**） |
| **验收门** | PII 扫描项逐条处置（改、删、或确认可保留）；化名映射表已单独存放且不在库目录内 |
| 不达标 | 未脱敏就入库 → 库内明文 + 云端 prompt 双重暴露；**删库不能撤回已发出的请求** |

《个人信息保护法》：健康、宗教、性取向、政治态度、违法经历等属敏感个人信息，需**单独同意**；知情同意书应写明"转写文本将用于 AI 辅助分析、可能经云端模型处理"。

### 步骤 3　格式规范化

| 项 | 内容 |
| --- | --- |
| 做法 | 编码统一 UTF-8；每轮单独成段；危险行首关键词括号化；过短小节并入相邻节；超长段落按句末标点补换行；可选按时间码自动分节 |
| 工具 | `_interview_norm.py fix`（**默认 dry-run，不覆盖原稿**） |
| 产物 | 规范化副本目录 + 计划/报告（逐文件列出改了几处） |
| **验收门** | 报告里"无法自动修复"为 0；自检 ERROR 从 N 降到 0；**原文每一行都还在** |
| 不达标 | 见 §4 逐条对策；"唯一小节且不足 40 字符"这类**无法自动修复**，需人工补内容或删标题 |

### 步骤 4　入库前自检（**干跑，不建库**）

| 项 | 内容 |
| --- | --- |
| 做法 | 用**引擎自己的函数**（`read_document`/`extract_meta`/`chunk_document`）干跑，复刻 `_ingest_file` 的块内去重，预测每个文件的块数、section 分布、将被丢弃的节、最大块长、元数据 |
| 工具 | `_interview_check.py`（只读；不建库、不下载模型、不改原稿） |
| **验收门** | ❌ 数 = 0（尤其是 `E_ZERO_WEIGHT_SECTION`/`E_TINY_SECTION`/`E_MEGA_CHUNK`/`E_FALSE_HEADING`/`E_ENC_UNKNOWN`） |
| 不达标 | 回到步骤 3。**不要"先入库看看"**——丢弃是静默的，入库后你只会看到"材料变少了"却不知道少了什么 |

### 步骤 5　入库

| 项 | 内容 |
| --- | --- |
| 做法 | `kb_ingest`（DSH 工具）或引擎命令；一个项目**一个**库目录 |
| **验收门** | 文档数 = 应入库的数；**块数 = 向量数**；errors = 0 |
| 不达标 | 向量数 < 块数 → 嵌入模型没跑起来（离线/未缓存），此时检索只剩关键词路。重跑 `kb_ingest`（增量会补向量） |
| ⚠️ 陷阱 | `kb_root` 必须是**直接包含 `kb.sqlite` 的目录**（通常是 `<项目>/.kb`）。写错路径时引擎会 `mkdir` + 建一个空库，"看起来像库是空的"——本项目已踩过两次（出现过一个 32 KB 空壳库）。`_interview_verify.py` 用 `mode=ro` 打开，**路径错就报错、绝不创建** |

### 步骤 6　结构验收

| 项 | 内容 |
| --- | --- |
| 做法 | 库级体检：计数一致性、悬空块、无向量块、同 sha256 重复、盲文档、`(rescued)` 痕迹、巨型分块、**时间码覆盖率**、**说话人覆盖率**、元数据缺失面、解析器版本（`indexed_with` vs `PARSER_REV`）、与源目录对账 |
| 工具 | `_interview_verify.py --kb-root <项目>/.kb --src <转写稿目录>`（只读） |
| **验收门** | ❌ 数 = 0；时间码覆盖率与说话人覆盖率达标（建议 ≥90%）；`stale_kind` 为 `none` |
| 不达标 | 逐条按报告处置；路径失效（dangling）说明入库后改过文件名 |

### 步骤 7　检索验证

| 项 | 内容 |
| --- | --- |
| 做法 | 造一批"已知答案"的问题（每个配一个**只出现在一处**的预期片段），量 Top-1/Top-5 命中率；中英对照 |
| 工具 | `_interview_experiment.py --lab <实验目录> --src <转写稿> --questions questions.csv`（**独立实验库**，拒绝碰正式库） |
| **验收门** | 中文提问 Top-5 命中率达你的标准；**中英对比结果与你采用的提问语言一致** |
| 不达标 | 先查时间码/说话人覆盖率与巨型分块；再查问题是否"口语化到没有可检索词" |

## 3. 工具总表

### 3.1 本次新增（4 个，均带 `--selftest`，均**自动定位引擎**、无项目路径硬编码）

| 工具 | 用途 | 自测 |
| --- | --- | --- |
| `_interview_check.py` | **入库前自检**：用引擎函数干跑，预测块数/section/将丢弃的节/最大块长/元数据/PII | **21/21** |
| `_interview_verify.py` | **访谈库结构验收**（只读，`mode=ro`，路径错不建库） | **23/23** |
| `_interview_norm.py` | **模板生成 + 规范化**（dry-run 默认，不覆盖原稿） | **31/31** |
| `_interview_experiment.py` | **最小验证实验**：独立实验库入库 + 中英对照检索 | **16/16** |

引擎定位顺序：`--engine` → 环境变量 `KB_ENGINE` → `~/.dsh/profiles/*/node_modules/dsh-kb-rag/kb_engine.py` → `~/.dsh` 下任意深度。**没有写死 `<DSH_ROOT>\...`**（对照：`_toolkit` 下 49/83 脚本绑死了项目路径）。

### 3.2 可复用（原文献库工具，访谈场景仍适用）

`_kb_guard.py`（写库闸门，先 `--selftest` 再进出）、`迁移工作区.py`（改路径/改名）、`_kb_meta_gaps.py`、`kb_ingest`/`kb_search`/`kb_rag`、备份与增量入库思路。

### 3.3 不可用（访谈材料上没有输入对象）

OCR 那条线共 10 个工具（`ocr_pdf_to_md`、`ocr_layout`、`page_number`、`docx_pages_index`、`resolve_full_pages`、`verify_ocr_pages`、`verify_page_offset` …）、`_fix_reversed_pages.py`、以及 `验收.py` 的页码类检查。

> `验收.py` 查"页码覆盖率/页码倒挂"；访谈库页字段恒为 NULL，那些检查**没有对象**。访谈库用 `_interview_verify.py`。

## 4. 五类静默失败（源码定位 + 复现证据 + 对策）

这五条是本方法存在的理由。全部经**自测复现**（不是推测）。

| # | 症状 | 引擎原因（源码位置） | 自检代码 | 对策 |
| --- | --- | --- | --- | --- |
| 1 | **整节材料不进库** | `chunk_document._emit()`：`if ww <= 0 and sec != "References": return []`；而 `SECTION_MAP` 把「附录/致谢/参考文献」映射为 weight 0 | `E_ZERO_WEIGHT_SECTION` | 标题里别用这些词开头；写成「（附录）受访者情况表」——关键词不在行首即不命中 |
| 2 | **短轮次小节消失** | 同函数：`if len(body) < 40: return []` | `E_TINY_SECTION` | 短促轮次并进相邻的、正文足够的节（`--merge-tiny`）；**整篇都短则无法自动修复**，需补内容 |
| 3 | **一个上万字的巨型分块** | `split_long` 按 `(?<=[。；.!?])\s+` 切——**要求句末标点后有空白**；中文「。」后通常没有空格，于是切不开 | `E_MEGA_CHUNK`（阈值 1200 字符） | `--split-sentences`：超长段落按句末标点补换行（引擎 `clean()` 把换行折成空格 → 成为切点）。**只插空白，不增删文字** |
| 4 | **静默乱码** | `read_document` 依次试 `utf-8-sig → utf-8 → gb18030 → utf-8(errors="replace")`；而 **gb18030 几乎能解出任何字节序列**，"成功"解码 = 乱码且不报错（Big5 稿就是这样） | `W_ENC_NON_UTF8` | 统一转 UTF-8；非 UTF-8 源必须显式 `--decode-as <编码>`，否则输出的是乱码 |
| 5 | **正文被当标题、首词被吃掉** | `match_section_prefix` 对**每个段落**生效（不只是标题行），短段落（去编号后 ≤80 字符）以「结果/总结/背景/方法…」开头即被当成章节标题：首词进 section、`section` 被切换 | `E_FALSE_HEADING` | **每轮以「说话人：」开头**（如 `A03：结果他就走了。`）——首词不再是章节名；顺带获得说话人归属 |

**另外两条必须知道的行为（不是缺陷，但影响使用）**

- **结果层去重**：`_search_core` 对每个 `doc_id` 只保留最高分的一块（`if r["doc_id"] in seen_docs: continue`）。访谈库里意味着"同一次访谈只出现一条结果"——要跨片段查得靠 `filters` 或提高 `top_k`。
- **命中的是片段不是全文**：结果只给 `snippet`（默认 300/400 字符，上限 2000）。做逐字引用时要请求足够宽度，否则预期片段可能被截断（本方法的实验用 1500）。

## 5. 转写稿格式规范（写稿就照这个）

```
# A03 - 2024-03-11 - 首次访谈          ← 文件名只用年份；完整日期放这里

## [00:00:00] 开场与知情同意              ← 标题带时间码 → section 就带时间码

A03：[00:00:00] 先说明一下，这次访谈完全自愿，任何问题都可以不回答。
B01：好的，我明白，那我们开始吧，我会尽量把当时的情况讲清楚。

## [00:12:35] 家庭背景

A03：[00:12:35] 你小时候家里一共几口人，父母当时是做什么工作的？
B01：五口人，我排行老二，父亲在供销社上班，母亲在家种地，日子过得不算宽裕。
```

| 规则 | 为什么 |
| --- | --- |
| 文件名 `受访者代号 - 年份 - 会话名` | 引擎按 `^作者 - 年份 - 标题$` 自动解析 `authors/year/title`（**只用年份**：`A03 - 2024-03-11 - …` 会被解析成 year=2024、title=`03-11 - …`） |
| 小节标题 `## [时:分:秒] 主题` | `section` 字段带时间码 → 检索结果可见、可用 `filters.section` 定位 |
| 每轮单独一行、单独一段（轮间空行），以「说话人：」开头 | 一次解决三件事：首词不是章节名（不被误判）、证据可归属到人、段边界成为切分点 |
| 标题开头避开「附录/致谢/参考文献」 | 命中 weight=0 → **整节丢弃** |
| 标题开头避开「摘要/引言/背景/结果/讨论/结论/总结/小结」 | 会被映射成学术章节名并**改变权重**（如「实验结果…」→Methods ×1.2） |
| 每节正文 ≥40 字符 | 不足 → 整节丢弃 |
| 通篇 UTF-8 | 其他编码有静默乱码风险 |

生成骨架：`python _interview_norm.py template --out <目录> --code A03 --date 2024-03-11 --session 首次访谈 --apply`
（未填写的模板**不会产生任何可检索块**——安全失败，不会污染库。）

## 6. 写库纪律与版本治理

- **改库前备份、先试运行、写完核对关键计数**（沿用文献库纪律）。访谈库的源材料（音频/转写稿）不可再生，**备份对象是源材料，而不是库**——库可从源重建。
- **解析器版本会变**：`docs.indexed_with` 记录入库时的解析器修订号；`CHUNK_AFFECTING_REVS` 里的修订**会改变分块与向量**。实测：引擎已升到 **3.2.0/rev5**，而示例人物库 114 篇全是 `3.1.0/rev4` → 引擎判定 `stale_kind = chunk`（**需要全量重灌，`metadata_only` 无效**）。
  → **对访谈库的直接教训：不要把编码/引文绑定到 `chunk.id`**（重灌一次全变），绑到**文本内容 + 时间码**上。
- **离线与模型**：引擎自己 `setdefault("HF_HUB_OFFLINE","1")`。要预下载重排模型（`BAAI/bge-reranker-base`，约 1.1 GB，**当前未缓存**）必须显式设 `HF_HUB_OFFLINE=0`，否则永远下不下来；而 deep 模式依赖它，在离线启动下会降级/失败。**日常用 quick 模式。**

## 7. 实测数字（2026-09-16，单机 CPU）

**环境**：引擎 3.2.0/rev5；`torch 2.13.0+cpu`，`cuda_available=false`，`embed_device=cpu`；嵌入模型 `BAAI/bge-small-zh-v1.5`。

| 指标 | 实测 |
| --- | --- |
| 样本 | 3 篇转写稿 / **7 块** / 7 向量 / 6 个问题 |
| 首次入库 | **7.03 s**（含模型加载；样本这么小，这个数字**不可外推**） |
| 纯处理速率 | **0.25 s / 7 块 → 每千块 ~36 s**（模型已在内存） |
| 模型加载开销 | 约 6.5 s（一次性） |
| 外推（**量级参考**） | 1 万块 ≈ 6 分钟；库内 1 万块量级的全量重灌是这个量级，不是小时级 |
| 中文提问 | Top-1 **6/6**，Top-5 **6/6** |
| 英文提问 | Top-1 **3/6**，Top-5 **4/6** |

**结论（限定在机制层面）**：纯中文访谈库上**中文提问优于英文提问**，与"文献库先转英文术语"的经验相反——机制解释：BM25 只对 **CJK 二元组**建索引（引擎注释原文），中文语料上英文查询关键词路空转，只剩向量侧跨语言匹配。

⚠️ **6 个问题、7 个块的规模只能验证"机制通不通"，不能得出检索质量结论。** 要谈质量必须用你自己的转写稿与问题（`--src` + `--questions`）。

完整报告：`访谈库实验_20260916\实验结果.md`

## 附：本方法的验证证据

| 结论 | 证据类型 | 可复现方式 |
| --- | --- | --- |
| 五类静默失败确实存在 | 源码逐条定位 + 自测造样本复现 | 各工具 `--selftest` |
| 规范化能把 ERROR 归零 | 自测里"修前 ERROR > 0 → 修后 = 0"的断言 | `_interview_norm.py --selftest` ⑧⑧a⑨⑪d⑪e |
| 规范化不丢字 | 自测断言：原文逐行核对 + 无净删字 | 同上 ⑩⑩a⑩c⑪g |
| 干跑预测与真实入库一致 | 干跑复刻 `_ingest_file` 的路径与块内去重 | `_interview_check.py` 源码 |
| 中文提问优于英文 | 实跑 6 问题 × 中英对照 | `_interview_experiment.py --lab ...` |
| 大批量重灌的量级 | force 重灌实测（模型已加载） | 实验报告 §一 |
