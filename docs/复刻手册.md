# 在另一台电脑复现「文献库」流程 · 保姆级操作手册

> **这份手册写给谁**：不熟悉电脑命令行的人。照着一步步抄，每步都告诉你**怎么知道成功了**。
> **目标**：在新电脑上建起同样的能力——把扫描的书刊/论文变成"能搜、能按书页页码引用"的数据库。
> **配套文件**：`检查环境.ps1`（体检）、`启动DSH.ps1`（启动）、`迁移_改路径.py`（换电脑/换盘符时改路径）。
> **想彻底搞懂原理、数据库功能与模型运用**：读同目录下的 `文献库完全操作指南.md`（约 1.9 万字，含 10 个工具详解、5 个模型说明、实操演练与 30 问 FAQ）。
> **技术依据**：本手册所有版本号与命令，都是在已跑通的机器上实测得到的，不是估计值。

---

## 第 0 步：先用三分钟看懂这件事

### 0.1 这套系统由三个零件组成

| 零件 | 通俗解释 | 在本机是什么 |
| --- | --- | --- |
| **Python** | 真正干活的程序：读 PDF、认字（OCR）、算页码 | Python 3.14.7，装在 `C:\Python314\` |
| **DSH** | 指挥台：你在这里跟 AI 说话，AI 去指挥 Python | 版本 0.1.1-rc.2，浏览器打开 `http://127.0.0.1:3080` |
| **文献库** | 一个文件夹，里面有个 `kb.sqlite` 文件，存着全部文字和页码 | `<DSH_ROOT>\example-project\.kb\kb.sqlite` |

### 0.2 一句话原理

> 你把 PDF 放进"素材文件夹" → DSH 里的工具调用 Python 把 PDF 认成文字 → 文字连同**页码**写进 `kb.sqlite` → 以后你提问，AI 从 `kb.sqlite` 里找答案，并能告诉你"这句话在原书第 X 页"。

### 0.3 最重要的一条规律（记不住别的，记住这条）

> **数据库放在哪个文件夹，决定了 AI 能不能自动找到它。**
> 规则：AI 默认去「你打开会话的那个工作区」下面的 `.kb` 文件夹里找 `kb.sqlite`。
> 所以本手册把库放在 `<DSH_ROOT>\example-project\.kb\`，以后在这个工作区里问话，**不需要额外指定路径**。

## 第 1 步：准备（10 分钟）

### 1.1 确认新电脑符合条件

- Windows 10 或 Windows 11，**64 位**
- 空闲硬盘空间 **至少 20 GB**（模型约 100 MB；OCR 与大库会占更多）
- 能联网（只有第一次需要，用来下载安装包和模型）

### 1.2 需要下载两个安装包

| 装什么 | 去哪里下 | 注意 |
| --- | --- | --- |
| **Python 3.14** | `python.org` → Downloads → Windows | 安装时**务必勾选** `Add python.exe to PATH` |
| **Node.js 24 LTS** | `nodejs.org` → LTS 版 | 一路"下一步"即可 |

> ⚠️ **用户名尽量不要用中文**。旧版安装脚本遇到中文用户名会出错（现已修复，但用英文名最省事）。如果新电脑的用户名已经是中文，不用重装系统，继续照做即可，出错时看第 10 节。

### 1.3 建一个统一的根目录

后面所有东西都放在 `<DSH_ROOT>\` 下面（**强烈建议保持这个结构，能省掉大量改路径的麻烦**）：

打开"文件资源管理器"→ 进入 D 盘 → 新建文件夹 `deepseek`。

✅ **成功的样子**：`<DSH_ROOT>` 这个文件夹出现了。

1. 双击下载好的 Python 安装包。
2. **勾选最下面的 `Add python.exe to PATH`**（这一步不勾，后面全部命令都会报"找不到 python"）。

**验证**：按 `Win + R`，输入 `powershell`，回车，出现蓝色/黑色窗口。把下面这行**复制粘贴**进去，回车：


✅ **成功的样子**：显示 `Python 3.14.7`（版本号接近即可）。
❌ **如果显示"无法将 python 项识别为..."**：说明 PATH 没勾。重新运行安装包 → 选 `Modify` → 确保 `Add to PATH` 被选中。

**验证**：

```powershell
dsh --version
```

✅ **成功的样子**：显示版本号（如 `0.1.1-rc.2`）。

## 第 5 步：安装"文献库"核心插件（决定成败的一步）

### 5.1 装 kb-rag 插件（含 Python 依赖）

在 PowerShell 里粘贴：

```powershell
npx --yes --package dsh-kb-rag -c "dsh-kb-rag-install --profile web"
```

这条命令会自动做三件事：装 DSH 插件、检查并安装 Python 依赖（PyMuPDF、numpy、faiss、sentence-transformers、torch）、下载所需模型。

> **国内网络慢或卡住**？加镜像参数（每个参数都是可选的）：
> ```powershell
> npx --yes --package dsh-kb-rag -c "dsh-kb-rag-install --profile web --Mirror https://pypi.tuna.tsinghua.edu.cn/simple"
> ```
> 下载模型慢时，可先设镜像环境变量再重跑：
> ```powershell
> $env:HF_ENDPOINT="https://hf-mirror.com"
> ```

### 5.2 装"工具库"插件（本流程的脚本总台）

```powershell
dsh plugin --profile web add file:<REPO>/tools/plugin
```

> 前提：`<REPO>/tools` 这个文件夹已经从旧电脑拷过来（见第 6 步）。如果还没拷，先做第 6 步再回来执行这条。

### 5.3 装其余插件（按需要）

```powershell
dsh plugin --profile web add dsh-cite dsh-lit-search dsh-ai4scholar dsh-paper-reader dsh-academy dsh-win32
```

**必需 / 推荐 / 可选对照**：

| 插件 | 作用 | 要不要装 |
| --- | --- | --- |
| `dsh-kb-rag` | **文献库本体**（入库、检索、问答） | **必需** |
| `dsh-toolkit` | 工具库（90+ 个脚本的统一入口） | **必需** |
| `dsh-win32` | Windows 平台运行时（kb-rag 依赖它） | **必需** |
| `dsh-cite` / `dsh-lit-search` / `dsh-ai4scholar` | 引文格式化 / 文献检索 / 学术工具 | 强烈推荐 |
| `dsh-paper-reader` | 英文文献逐段精读 | 推荐 |
| `dsh-academy` | 学术模式（人设 + 防编造引用） | 推荐 |
| `dsh-plugin-academic-writing` | 学术写作工具包 | 可选（旧电脑上此项**有缺陷**，见第 10 节） |
| 其他（univer、pet、market 等） | 表格/演示/养成/插件市场 | 可选 |

### 5.4 打一个关键补丁（不打，kb-rag 会静默不工作）

新建/编辑文件 `C:\Users\<你的用户名>\.dsh\profiles\web\cordis.patch.yml`，把下面内容**整段**粘进去（如果文件已有内容，把这两段追加到末尾）：

```yaml
- id: academy
  config:
    persona: true
    integrity: true
    language: true
    field: 政治学、社会学
    personaOrder: 0
    rulesOrder: 120

# subprocess 服务修复：不修的话 kb-rag 在启动阶段会放弃注册全部工具，
# 宿主日志出现 "subprocess service unavailable; tools not registered"
- id: subprocess
  disabled: false
- id: subprocess-windows
  disabled: true
```

> 为什么必须打：`dsh-win32` 会停用平台自带的 `subprocess` 服务行、改用自己的一条，但那条位于不同补丁层，**所有插件都取不到**。实测证据：连排在最末尾的插件都拿不到该服务，kb-rag 因此直接放弃注册。这两行的作用是把平台那行恢复、把替代行停用。

✅ **成功的样子**：文件保存后，文本里同时有 `- id: subprocess` 和 `- id: subprocess-windows` 两段。

## 第 8 步：跑一遍完整流程（精简 5 步）

### 8.1 启动 DSH 并打开工作区

```powershell
<DSH_WORKSPACE>\启动DSH.ps1
```

（没有这个脚本就手动执行 `dsh web`。）
然后浏览器打开 `http://127.0.0.1:3080`，**新建会话时把工作目录选成 `<DSH_ROOT>\example-project`**。

> 这一步很关键：**会话开在哪个工作区，AI 就默认用哪个工作区的 `.kb` 数据库**。

### 8.2 入库

在会话里对 AI 说：

> 把 `01_文献` 里的文件全部入库。

AI 会调用 `kb_ingest`，把文件分块、算向量、写进 `<DSH_ROOT>\example-project\.kb\kb.sqlite`。

✅ **成功的样子**：AI 报告"新增 N 篇、跳过 M 篇、错误 0"。

### 8.3 核查

说：

> 检查知识库结构和元数据。

✅ **成功的样子**：给出文档数、块数、向量数，且"悬空文档 0、chunk_count 不一致 0"。

### 8.4 检索验证（必做）

说一句你确定书里有的原话，要求逐字检索。

✅ **成功的样子**：能命中，并给出**文件名 + 页码**。
❌ 如果命中不了，多半是 OCR 或页码问题，见第 10 节。

### 8.5 备份（养成习惯）

入库前 AI 应自动备份。手动备份也行：把 `.kb\kb.sqlite` 复制一份，改名成 `kb.sqlite.bak-日期`。

## 第 9 步：换电脑/换盘符后，必须改路径（重要）

**为什么会需要**：数据库里记着每篇文献的"绝对位置"（例如 `<DSH_ROOT>\...`）。新电脑如果盘符或用户名不同，这些位置就全部失效——AI 还能搜到内容，但**给出的文件路径点不开**。

### 9.1 用配套脚本改（推荐）

```powershell
python <DSH_WORKSPACE>\迁移_改路径.py --old "<DSH_ROOT>\example-project" --new "E:\研究\example-project"
```

- 默认**试运行**，只打印会改什么，不动手；
- 确认无误后加 `--apply` 真正执行；
- 它会同时处理：数据库里的路径、以及脚本文件里的硬编码路径。

### 9.2 改完必须验证

```powershell
python <DSH_WORKSPACE>\迁移_改路径.py --old "<DSH_ROOT>\example-project" --new "E:\研究\example-project" --verify
```

✅ **成功的样子**：显示"磁盘上找不到的文献：0 条"。

> ⚠️ **两个绝对不要改的东西**：`.kb` 目录名 和 `kb.sqlite` 文件名。AI 的工具写死了这两个名字，改了库就找不到了。**要改名字就改 `.kb` 外面那层文件夹**（这正是本手册把工作区叫"example-project"的原因）。

## 第 10 步：出问题怎么办（故障排查表）

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 提示 `无法将 python 项识别为...` | 安装 Python 时没勾 PATH | 重跑安装包 → Modify → 勾 Add to PATH |
| 提示 `无法将 npm 项识别为...` | 装完 Node 没重开窗口 | 关掉 PowerShell，重新开一个 |
| AI 说"知识库为空" | **最常见**：会话工作区选错了，AI 去别处找了 | 确认会话工作区 = 数据库所在文件夹；或明确告诉 AI `.kb` 的完整路径 |
| 搜索没有结果，但文件确实入库了 | 库路径写错，AI 生成了一个空库 | 检查是不是多出了空的 `.kb` 文件夹（见下方"空壳陷阱"） |
| `dsh-kb-rag-install` 报 E404 | npm 缓存了旧信息 | 先 `npm cache clean --force` 再重试 |
| 安装时报 `WinError 123` 且用户名是中文 | 旧版脚本不支持中文用户名 | 重跑安装命令（新版已修复）；仍失败就换英文用户名 |
| 工具调用报 `userRender is not a function` | 工具库插件与 DSH 版本的接口不匹配 | **改用命令行**：`python <REPO>/tools\toolkit.py list`（功能不受影响） |
| 学术写作工具报 `value is not lossless JSON` | 该插件自身缺陷，与本流程无关 | 不用它，或等插件更新 |
| OCR 很慢 | 正常现象 | 一页约 5–15 秒；1000 页的书要几小时，可放着过夜 |
| 检索"卡住不返回" | 引擎在联网下载未缓存的模型 | 关掉再试；或按 10.1 设置离线环境变量 |

### 10.1 空壳陷阱（务必知道）

AI 的工具在**找不到数据库时会自动新建一个空库**，且不会报错。所以：

- 如果你发现某个文件夹里**莫名多出一个很小的 `kb.sqlite`（几十 KB）**，那就是空壳，说明路径传错了。
- 判断办法：真正的库是几十 MB 以上；空壳只有几十 KB。
- 处理：删掉空壳，重新用正确的工作区/路径操作。

### 10.2 建议设成离线模式（避免联网卡死）

在启动 DSH 之前，先在 PowerShell 里执行：

```powershell
$env:HF_HUB_OFFLINE="1"
$env:TRANSFORMERS_OFFLINE="1"
```

`启动DSH.ps1` 已经帮你设好了这两项。

## 第 11 步：日常怎么用

| 你想做的事 | 怎么做 |
| --- | --- |
| 加新文献 | 把文件丢进 `01_文献`，然后对 AI 说"把新增文件入库" |
| 查一句话出自哪本书哪一页 | 对 AI 说"逐字检索：……"，并要求用关键词模式 |
| 概念性查找 | 直接问，AI 用语义检索 |
| 给论文引文补页码 | 说"帮我核对这些引文在原书第几页" |
| 备份 | 复制 `.kb\kb.sqlite`，改名加日期；或让 AI 执行备份 |
| 换电脑 | 拷 `.kb` + 做第 9 步改路径 |

**三条使用纪律**（能避免绝大多数事故）：

1. **改库之前先备份**——AI 的写操作脚本会自动备份，你自己手动改前也要备份。
2. **不确定的页码宁可留空**，不要让它"猜一个看起来对的"。
3. **写完立刻核对数量**——文档数、块数不增反减，说明出问题了。

## 第 12 步：这份流程里"搬不过去"的东西（诚实清单）

换电脑**不能**照抄的部分，必须重做或重新确认：

| 项目 | 情况 | 怎么办 |
| --- | --- | --- |
| `kb_engine.py` 的本地补丁 | 本机的引擎文件**被改过**（强制离线加载、避免联网卡死），与官方包不一致 | 要么拷这个文件覆盖，要么照着第 10.2 设置环境变量 |
| 重排序模型 | `bge-reranker-base` **本机没有缓存**，深度检索实际上会降级 | 想要更好的排序就联网下载该模型；不装也能用 |
| HuggingFace 模型 | `bge-small-zh-v1.5`（92 MB）需重新下载 | 首次运行会自动下载；慢就设 `HF_ENDPOINT=https://hf-mirror.com` |
| OCR 模型 | 随 `rapidocr-onnxruntime` 包自带（约 13 MB） | 装包即得，无需额外操作 |
| DSH 插件补丁 | `cordis.patch.yml` 必须手工照抄（第 5.4 步） | 否则 kb-rag 不注册工具 |
| 工具脚本的硬编码路径 | 90+ 个脚本里有大量写死的旧电脑路径 | 用第 9 步的脚本批量改 |
| 历史备份 | 旧电脑的备份已按需清理 | 新电脑上从零开始积累 |
