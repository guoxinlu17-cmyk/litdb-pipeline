中文 · [English](README.en.md)

把**扫描件 / PDF / Word** 变成一份**带着印刷页码的文本**，让检索出来的每一段话都能回答
「它在原书第几页」——并且能一路回填进论文的引注里。

---

## 它解决什么问题

你从扫描版的书里摘了一段话写进论文，标注「第 294 页」。三个月后审稿人问起，你回去检索——
**搜到了那段话，但没法确认它就是第 294 页那一页上的**。因为：

- OCR 出来的页码是 **PDF 页序**，不是书上印的页码；
- 书上第 294 页在 PDF 里可能是第 301 页（前有版权页、序言、目录）；
- 每卷的偏移量还不一样。

这个项目把这条线焊死：**页码在文本化阶段就落进文本标记**，一路贯通到检索结果的
`section` 字段。检索「第 294 页」，拿到的就真是书上的第 294 页。

### 输入 → 输出长什么样

输入是一份「一页一节、页眉印着页码」的 docx（或一份无文字层的扫描 PDF）。

输出是带页标记的 Markdown：

```markdown
#### 第 293 页

【页眉】日 记 643
……正文……

#### 第 294 页

【页眉】644 某某文集
……正文……

> **来源与可信度说明（务必先读）**
> - 本文件**不是 OCR 结果**：由转换件按页重建，共 812 页。
> - 页码标记为标题行 `#### 第 N 页`：N 是**书页上印的页码**（取自该页页眉），
>   不是 PDF 页序；**使用本文件时偏移量为 0**。
> - 无页码的节一律归入其前一个带页码的页，**只归并不插值，故不会编造页码**。
> - **引用仍须回查纸本**：文本来自扫描转换，可能有误识。
```

用**标题**而不是分隔线标页，是为了让切块器把它抽成 `section`——检索结果里直接显示命中页。

## 两半，可以分开用

这个仓库由两半组成，**只有前半是必需的**：

### 前半 · 文本化与页码锚定 —— 独立可用，只需 Python

```
PDF / 扫描件 / docx
      │
      ├─ 体检：页数、有无文字层、版式类型
      ├─ 版式预检：栏数 / 通栏 / 页眉页脚 / 竖排
      ├─ 文本化：版式感知 OCR ｜ docx 页眉法 ｜ OCR 转印刷页码
      └─ 页码标定：投票求偏移 + 结构校验
      ↓
带印刷页码标记的 Markdown  ← 你可以拿去喂 Obsidian、grep、任何 RAG 系统
```

**这一半不依赖任何外部引擎。** 产出的就是纯文本，爱怎么用怎么用。

### 后半 · 接知识库做检索与引文定位 —— 可选

如果要的是「跨卷检索 + 引文自动定位 + 逐字校勘 + 页码回填」，需要再接一个知识库引擎
（本项目用的是 DSH + `dsh-kb-rag`，见「可选：接知识库引擎」）。**不接也能用前半。**

## 两条不变式

整条流水线只守这两条，其余都是实现细节：

> **不变式 1：页码是主线。**
> 从扫描页开始，页码就要落进文本标记，一路贯通到入库后的 `section` / `page_start`，
> 再到论文里的引文标注。**这条线一断，后面全是猜**。

> **不变式 2：宁可留空，不可猜测。**
> 最危险的不是「读不出来」，而是「**读错但看起来对**」。所以：读不出来 → 如实记 `status`；
> 推不出页码 → 留 `NULL`；没核实 → 标「待回查纸本」。

若你的项目不需要「引文可回查纸本」，可以砍掉版式预检与页码统一两步，
但**不要**用「承前/承后」之类的兜底去伪造页码。

## 五层架构

```
L1 素材层    原始 PDF / DOCX / 扫描件 / 已有 Markdown
                 ↓  体检：页数、有无文字层、版式类型
L2 文本化层  三条并行路线，按素材类型择一（可混用）      ┐
                 ① 版式感知 OCR        ← 无文字层的扫描件 │ 这
                 ② docx 页眉法（免OCR） ← 一页一节且页眉带页码 │ 半
                 ③ OCR 文本转印刷页码   ← 已有 OCR 但页码是 PDF 页序 │ 独
                 ↓  产出：逐页文本 + 页标记 + 质量报告            │ 立
L3 结构层    分块 + 页码字段 + 向量      ← 需要外部引擎   ┘
                 ↓
L4 应用层    检索 / 引文定位 / 逐字校勘 / 页码回填 / 二级文献抽取
                 ↓
L5 治理层    结构核查 / 去重 / 元数据修复 / 备份与回滚
```

## 快速开始

### 第 0 步：先看它做什么（**不需要配置任何东西**）

```bash
git clone https://github.com/guoxinlu17-cmyk/litdb-pipeline.git
cd litdb-pipeline
python examples/demo.py
```

`demo.py` 会在临时目录里生成一份**合成样例**（一页一节、页眉印着页码的 docx），
然后跑完「建逐页索引 → 写出带页码标记的 Markdown」，并把结果打印出来。

样例只有 6 页，但页眉里的印刷页码是 **101–106**——所以你会直观看到本项目的主张：

> **页码从哪来？不是 PDF 页序，是书页上印着的那个数字。**

样例是脚本现生成的合成数据，不含任何真实书籍内容。

### 第 1 步：确认工具箱本身是好的

```bash
python run_selftests.py
```

它同样在**临时目录**搭一个最小项目骨架再跑自测，与你的项目长什么样完全解耦。
8 个工具、约 186 项断言，全绿再往下走。

### 第 2 步：装依赖

```bash
# 最小：只走 docx 页眉法 + 核查线
pip install python-docx

# 完整：再加 OCR 线
pip install pymupdf rapidocr_onnxruntime numpy pillow
```

| 包 | 用途 | 谁需要 |
| --- | --- | --- |
| `python-docx` (`docx`) | docx 解析 | 路线②、md2docx |
| `PyMuPDF` (`pymupdf` / `fitz`) | PDF 渲染与文本抽取 | OCR 线、体检 |
| `rapidocr_onnxruntime` + `numpy` + `Pillow` | 版式感知 OCR | 路线① |

### 第 3 步：配置你的项目

工具需要知道素材、题录库、论文各在哪。

```bash
# 推荐：在项目根放一个 项目布局.json
cp 项目布局.json.example <你的项目根>/项目布局.json
# 然后改里面的路径

# 或者用环境变量
setx LITDB_PROJECT "<你的项目根>"

# 验证解析结果（未解析出的会说明原因）
python tools/_paths.py
```

> ⚠️ **不配置就跑工具会报 `PathError`**，部分工具连 `--help` 都会报。
> 这是刻意的：**宁可报错，不要猜路径**。详见「已知限制」。

### 第 4 步：按 SOP 走

**动手前读一遍** [`docs/SOP.md`](docs/SOP.md)——十二步流程、每步的验收门、失败模式、检查清单、速查命令。

## 这个项目的几个非显然结论

都是实测出来的，写在 SOP 里，也是这套流程存在的理由：

1. **「未入库」≠「被遗漏」。** 曾把两篇「缺失文献」当成缺口，实为纯图像（只能提取出 19 字、39 字）。
   先看 `status`，再谈缺口。

2. **引号配对要在全文做，不能在小窗口做。** 直引号开闭同形，窗口内奇数个就整体错开一位——
   抓到的其实是引文**前面**的正文。这类错位不报错，只是安静地给你错的页。

3. **省略号不能当噪声删。** 论文用「……」跳过若干字，删号后前后两截被强行接成一句，
   永远对不上。要先按省略号切段、逐段定位，再核对各段是否同页。

4. **引擎提示「建议重灌」时不要照着做。** 实测页锚点覆盖率会从约 97% **静默**掉到约 23%，
   需要两步回填才能救回（可回到约 97%）。标准动作见 [`docs/SOP.md`](docs/SOP.md) §12。

5. **引文校勘几乎必然发现问题。** 实测会出现 1–2 处实质讹误或文本归属错误——
   这正是设「逐字校勘」与「交叉验证」两步的原因，不是流程没做好。

## 可选：接知识库引擎

只有想做「跨卷检索 + 引文定位 + 页码回填」时才需要。本项目的实现方式是通过一个
JSON-over-stdin 协议驱动 **DSH（DeepSeek Harness）的知识库插件 `dsh-kb-rag`**：

- 引擎文件：`<DSH profile>/node_modules/dsh-kb-rag/kb_engine.py`
- 对话侧工具：`kb_ingest` / `kb_search` / `kb_stats` / `kb_rag` / `kb_dedup` / `kb_fetch`
- **保底通道**：插件失效时用 `tools/kb_cli.py` 直接在命令行驱动（`stats` / `ingest` / `search` / `rag`）

引擎位置可用 `--engine` 参数或 `KB_ENGINE` 环境变量指定。

> **接口是可替换的。** L3 只要求一个能「按页标记切块 + 存页码字段 + 支持按 section 过滤」
> 的后端。换成别的向量库或全文检索，L1/L2 与 L4/L5 都不用动——改的只是一个
> JSON 协议的适配层。

## 已知限制

1. **44 个工具里有 17 个无法在未配置项目时运行**（实测：`--help` 可用 27 个／被挡 17 个）。
   路径解析已改为**惰性**（`LazyPath`，第一次用到时才解析），所以 `--help` 这类调用不再触发
   解析；剩下被挡的是**模块级就真的去读库**的审计类工具——没有数据库它们本来就干不了活。
   配置好后即可用（见「快速开始·第 3 步」），或直接跑 `python run_selftests.py` 自检。

2. **工具大多绑定项目结构**，不是拿来即用的通用件。复用 = 复用流程与思路 +
   按需参数化脚本。分级依据见 [`docs/SOP.md`](docs/SOP.md) §5。

3. **页码偏移量因卷而异**，必须逐卷自证（判据：命中页文本里真的印着推算出的页码，
   且差值成片而非散点）。**不要照抄任何示例里的偏移值。**

4. **重灌会静默摧毁页锚点**（见上文「非显然结论」第 4 条）。

## 数据与隐私

**本仓库只含流程与工具，不含任何文献内容或研究数据。**

- 文档里的 `示例文集` / `示例人物` / `topic-a` 等是**占位符**。
- 代码里的「引文 + 页码」用例已全部外置为**外部 JSON**（`*_cases.json`），仓库不内置真实引文。
- 实测数字（文档数、块数、卷数、各卷偏移量）一律为量级区间。

**你自己使用时请注意**：

- `.gitignore` 已排除 `.kb/`、素材目录、题录库 CSV 与论文稿——**别把它们提交上去**。
  扫描件与 OCR 文本常涉及版权；未发表论文与访谈稿涉及隐私。
- **访谈材料必须在入库之前脱敏**：检索片段会进云端模型的 prompt，
  用了这套工具就不是「本地封闭处理」了。`_interview_check.py` 会检出手机号/邮箱并警告。
